# 3.1 Introduction and Transport-Layer Services

A transfport-layer protocol provides for logical communication between processes running on different hosts.

By logical communication, we mean application processes use the logicla communication provided by transport
layer to send messages to each other, free from the worry of the details of the physical infrastructure.

Transport layer protocols are implemented in the end systems but not in network routers.

On the sending side:   
The transport-layer converts application-layer message into transport-layer packets (aka segments).
This is done by breaking application messages into smaller chunks and adding transport-layer header to
each chunk.

A segement = a small chunk + a header

The transport layer passes the segment to the network layer at the sending end system,
where the segment is encapsulated within network-layer packet(a datagram) and sent to the destination.

> The network routers act only on the network-layer fields of the datagram.
> They do not examine the fields of the transport-layer segment.

On the receving side:   
The network layer extracts the transport-layer segment from the datagram and passes the segment up to the
transport layer.
The transport layer processes the received segment, making the data in the segment available to the receving
application.

## 3.1.1 Relationship Between Transport and Network Layers

The transport layer lies just above the network layer in the protocol stack.

The transport layer povides logical rather than physical communication between application processes.

Transport layer - The logical communication between processes running on different hosts.
Network layer - The logical communication between hosts. 

A nice anology for explaining how the transport layer relates to the network layer:
- application messages = letters in evelopes
- processes = cousins
- hosts (end systems) = houses
- transport-layer protocol = Anna and Bill
- network-layer protocol = postal service

## 3.1.2 Overview of the Transport Layer in the Internet

transport-layer packet = segment
transport-layer packet TCP = segment = TCP packet
transport-layer packet UDP = datagram = UDP packet

> A few words about the network layer.
> The internet protocol - IP providdes logical communication between hosts.
> The IP is a best-effort delivery service.
> IP is an unreliabley service.
> No guarantees: segment delivery, orderly delivery, integrity.

Every host has at least one network-layer address (aka IP address).

The most fundamental reponsiblity of UDP and TCP is to extend IP's delivery service between two
end systems, to a delivery service between two processes running on the end systems.

Extending host-to-host delivery to process-to-process delivery is called **transport-layer multiplexing**
and **demultiplexing**.

TCP, UDP povide integiry checking by error detection fields in segments's headers.

# 3.2 Multiplexing and Demultiplexing

The job of delivering the data in a transport-layer segment to the correct socket is called demultiplexing.

The job of gathering data chunks at source host from different sockets, encapsulating each data chunk with 
header information to create segments, and passing the segments to the network layer is called multiplexing.

A middle host must delultiplex and multiplex segments.

The transport-layer multiplexing requires that sockets have unique identifiers.
Each segment have special fields that indicate the socket to wich the segment is to be delivered.

These speical fields are the **source port number field** and **desitination port number field**.
Range port number: 0 - 65535 (16-bit number)
Well-known port numbers: 0 - 1023

### Connectionless Multiplexing and Demultiplexing

The client side of the application lets the transport layer automatically assign the port number,
whereas the servier side of the application assigns a specific port number.

UDP socket is identified by an IP address and a port number.
