# CHAPTER 3 Performance Schema

Every time you make a change to tune the performance of the database, you need to understand if the change
had any effect.
- Are your queries running faster than before?
- Are locks slowing down the application, or are they entirely gone?
- Did memory usage change?
- Did the time spent waiting on disk change?

Performacne Schema is a database that stores the data required to answer these questions.

# Intorduction to Performance Schema

Performance Schema provides low-levle metrics on operations running inside MySQL server.

To explain how Performance Schema works, you need to know:
- instrument
- consumer

An instrument refers to any portion of the MySQL code that we want to capture information about.
For example, if we want to collect information about metadata lcoks, we would need to enable the wait/lock/metadata/mysql/mdl instrument.

Consumer, which is a table that stores the information what code was instrumented.
If we instrument queries, the consumer will record information like 
- The total number of executions
- How many times no index was used, 
- The time spent

# Instrument Elements

In performance_schema, the setup_instruments table contains a list of all supported instruments.

```sql
SELECT * FROM performance_schema.setup_instruments
WHERE DOCUMENTATION IS NOT NULL
```

# Consumer Organization

A consumer is the destination where an instrument sends its information. Performance Schema stores instrument results in many tables.

## Summary tables and digests

A summary table holds aggregated information about whattever teh table suggests.

Digests are a way to aggregate queries by removing the variations in them.

```sql
select user, birthdate from users where user_id=19;
select user, birthdate from users where user_id=20;
select user, birthdate from users where user_id=13;
```

The digest for this is:

```sql
select user, birthdate from users where user_id=?
```

### Instances

Instances refer to object instances, avaiable for the MySQL instalaltion.
For example the `file_instances` table contaisn filenames and the number of threads that access these files.

### Setup

Setup tables are used fo rruntime setup of `performance_schema`.

### Other tables

There are other tables whose anmes do not follow a strict pattern. For example, the `metadata_locks` table holds data about meta data 
locks.


# Resource Consumption

The data collected by Performance Schema is kept in memory. You can limit the amount of memory it uses by setting the maximum size
of the consumers.

Some tables in `performace_schema` support autoscaling.
