# 7.4 Stacking contexts and z-index

It's important to understand how the browser determines the stacking order.

## 7.4.1 Understanding the rendering process and stacking order

The brower parses HTML into the DOM, it also creates another tree structure called the
render tree.

This order is important because elements painted later appera in front of element painted
earlier, should they happen to overlap.

This behavior chagnes when you start positioning elements.

The browser first paints all non-positioned elements,
then it paints the positioned ones.

By default any positioned element appears in front of any non-positioned elements.

## 7.4.2 Manipulating stacking order with z-index

Elements with a higher z-index appear in front of elements with a lower z-index.

Elements with a negative z-index appear behind static elements.

z-index only works on positioned elements.
