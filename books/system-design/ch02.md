Sometimes you are asked to estimate system capacity or performance requirements using a 
back-off-the-envelope estimation.

## Power of two

2^40, 1 TB
2^50, 1 PB

## Latency numbers every programmer should know

The fastness and slowness of different computer operations.

ns: nano second
us: microsecond

L1 cache reference      0.5 ns
L2 cache reference      7 ns
Mutex lock/unlock       100 ns
Main memory reference   100 ns
Compress 1K bytes       10 us
Send 2K bytes over 1Gbsp network    20 us
Read 1 MB from memory   250 us  
Disk seek   10 ms
Read 1 MB from network      10 ms
Read 1 MB from disk      30 ms

Conclusions:
- Memory is fast, disk is slow.
- Avoid disk seeks if possible.
- Simple compression algorithms are fast.
- Compress data before sending over the internet if possible.
- It takes time to send data between data centers that are in different regions.

## Availability numbers

HA is the ability of a system to be operational for a long period of time.
HA is measured as a percentage.

A serice level agreement (SLA) is a term for service providers.
This is an agreement between you and your customers.
This agreement defines the level of uptime your service will deliver.

## Example: Estimate Twitter QPS and storage requirements

Assumptions:
- 300 million monthly active users.
- 50% of users use Twitter daily.
- Users post 2 tweets per day on avg.
- 10% of tweets contain media.
- Data is stored for 5 years.

Estimations:

Query per second (QPS) estimate:
- Daily active users (DAU) = 300 * 50% = 150 million
- QPS = 150 * 2 / 24 / 36000 = ~3500
- Peek QPS = 2 * QPS = 7000

Esstimate storage here:
- Average tweet size
    - tweet_id 64 bytes
    - text 140 bytes
    - media 1MB

- Media storage: 150M * 2 * 10% * 1MB = 30 TB per day

- 5 year media storage: 30 TB * 265 * 5 = ~55 PB

## Tips 

It is good idea to write down assumptions to be referenced later.
