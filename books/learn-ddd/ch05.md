# Transaction Script

> organizes businnes logic by procddures where each procedure handles request from the presentation.

## Implementation

Each procedure is implemented as a simple procedural script.
The procedures ahve to fulfill is transaction behavior.
Each operation should either succeed or fail but can never result in an invalid state.

For example a transaction script that ocnverts batches of JSON files.
```cs
DB.StartTransaction();

var job = DB.LoadNextJob();
var json = LoadFile(json.Source);
var xml = CovnertJsonToXml(json);
WriteFile(job.Destination, xml.ToString());
DB.MarkJobAsCompleted(job);

DB.Commit();
```

### Lack of transaction behavior

Easy to fix in a database.
Hard to fix in multiple storages, distributed transaction.

### Distributed transactions

The common practice to make changes to the data in a database and then notify other components of
the syste about the change by publising messages into a message bus.

```cs
class LogVisit {
    public void Execute(Guid userId, DataTime visitedOn)
    {
        _db.Execute("UPDATE Users SET last_visit=@p1 WHERE user_id=@p2",
            visitedOn,
            userId);
            // Error here
        _messageBus.Publish("VISITS_TOPIC",
            new { UserId = userId, VisitDate = visitedOn });
    }
}
```

Two problem raises:
- Publishing message fails
- Consumers fail

The CQRS pattern helps to polulate multiple storage.
The outbox pattern enables reliable publishing of messages after committing changes to another database.

### Implicit distributed transactions

```cs
public class LogVisit
{
    ...
 
    public void Execute(Guid userId)
    {
        _db.Execute("UPDATE Users SET visits=visits+1 WHERE user_id=@p1",
                    userId);
    }

```

One way to ensure transaction behavior is to make the operation idempotent.

```cs
public void Execute(Guid userId, long visits)
{
    _db.Execute("UPDATE Users SET visits=@p1 WHERE user_id=@p2",
                visits, userId);
}
```

Another way to address such an issue is to use optimistic concurrency control.

```cs
public void Execute(Guid userId, long expectedVisits)
{
    _db.Execute("UPDATE Users SET visits=vists+1 WHERE user_id=@p1 and visits = @p2",
        userId,
        expectedVists);
}
```

## When to Use Transaction script

The transaction script pattern is well adapted to the most straighforward problem domains
in which the business logic resembles simple procedural operations.

For example, in ETL operation.

# Active Record

> An object that wraps a row in a database table or view, encapsulate the database access, and
> adds domain logic on that data.

active record supports cases where the business logic is simple,
the business logic may operate on more complex data structures.

For example, instead of flat records.

Advertiser 1 
    |*
    |
    |*
Ad campaign 1---* Placement --- Website --- Zone
                    |*
                    |
                    |*
                Creative

Operation on such data structures via a simple trnsaction script wold result in
lots of repeat code.

## Implementation

This pattern uses dedicated objects, known as active records, to represent complicated
data structures.
Apart from the data structure, these objects also implement data access methods for creating,
reading, updating and deleting records - CRUD operations.

As the result, the active objects are coupled to ORM or other data access framework.

The system business logic is organized in a transaction script.
The difference between the two patterns is that in this case, instead of accessint the database
directly, the transaction script manipulates active record objects.
When completing, the operation has to either complete or fail as an atomic trasaction

```cs
public class CreateUser
{
    ...

    public void Execute(userDetails)
    {
        try
        {
            _db.StartTransaction();

            var user = new User();
            user.Name = userDetails.Name;
            user.Email = userDetails.Email;
            user.Save();    // notice this line

            _db.Commit();
        } catch {
            _db.Rollback();
            throw;
        }
    }
}
```

## When to use Active Record

Because an active record is a transactive script that optimizes access to databases, this pattern can conly support relative simple business logic, such as CRUD operation.

The active record supports 
- subdomains
- integration of external solution for generic domains
- modle transformation tasks
