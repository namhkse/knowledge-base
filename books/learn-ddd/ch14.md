# What is a service?

A service is a mechanism that enables access to one or more capabilities, where the access
is provided using a prescribed interface.

The prescribed interface is any mechanism for getting data in or out of a service.
It can be synchronous, such as a request/response model, or asynchronous such as model that
is producing and consumming event.

# What is a microservice?

A service is defined by its public interfaces, a microservice is a service with a micro-public
interface.

Easier to understand both the function of a single service and the integration with other system
component.

Reducing a service's functionality also limits its reasons for change and amkes the service
more autonomous for development.

## Method as a Service: Perfect Microservices?

Non one service is allowed to access another service's database directly, only through
its public interface. There is not publci interface for that. The service have to work
together and synchronize the changes each service is applying.
As a result, a big ball of mud.

## Design Goal

The goal of the microserces architecture is to produce a flexible system.

Mistake: create simple services, get complex systems.
We won the battle but lost the war.

## System Complexity

The local complexity of each microservice.
The global complexity of the whole system.

It's easy to reduce global complexity to a mininum. All we have to do is using one monolithic service.

## Microservice as Deep Servies

Effective modules are deep: a simple public interface encapsulates complex logic.

Ineffective modules are shallow: a shallow module’s public interface encapsulates much less complexity than a deep module.
