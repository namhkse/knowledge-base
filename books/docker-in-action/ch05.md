## 5.1.2 Bigger picture: networks, NAT, and port forwarding

Interfaces are single points in larger networks.

# 5.2 Docker container networking

Single-host virual networks: provide container isolation

Multi-host networks: any container can have its own routable IP address.

## 5.2.1 The local Docker network topology

The virtual netowrk is local to the machine where Docker is installed and is made up of routes between containers and teh wider network where teh host is attached.

Container --> Docker Virtual Network --> Host --> Ethernet --> Internet

A contaier has its own:
- private loopback interface
- ethernet interface.

Connections are routed through the Docekr bridge interface called *docker0*.

## 5.2.2 Four network container archetypes

- Closed containers
- Bridged containers
- Joined containers
- Open containers

# 5.3 Closed containers

Don't allow any network traffic.

Create a closed contaier wit the `--net none` option.

```sh
docker run --rm --net none alpine ip addr
```

Try to ping outside and fail
```sh
docker run --rm --net none alpine ping -w 2 8.8.8.8
```

# 5.4 Bridged containers

Bridged containers have a private loopback interface and another private interface.

All interfaces connected to docker0 are part of the same virtual nubnet.

## 5.4.1 Reaching out

The common reason to choose a bridged container is that the process need access to the network.

Use `--net bridge` or ormit, it is default.

```sh
docker run --rm --net bridge alpine ip addr
```

This time you see 2 intefaces: an Ethernet and a local loopback.

Try to ormit `--net`

```sh
docker run --rm alpine ping -w 2 8.8.8.8
```

## 5.4.2 Custom name resolution

DNS is a protocol for mapping host names to IP.

Unless you run your own DNS server, you can't refer containers by their names.

Option `--hostname`, you can use to it to set the host name of a new container.
This adds an entry to the DNS override system inside the container.

```sh
docker run --rm --hostname barker alpine nslookup barker 
```

Custome teh DNS configuration of a container.

```sh
$ docker run --rm --dns 8.8.8.8 alpine nslookup docker.com

Address:	8.8.8.8:53

Non-authoritative answer:
Name:	docker.com
Address: 23.185.0.4

Non-authoritative answer:
Name:	docker.com
Address: 2620:12a:8001::4
Name:	docker.com
Address: 2620:12a:8000::4
```

`--dns` supports multiple DNS server, values must be IP

`--dns-search` allow you to set default host name suffix.

```sh
docker run --rm --dns-search docker.com alpine nslookup registry.hub
# Lock up for registry.hub.docker.com
```

## 5.4.3 Opening inbound communication

Bridged containers aren't accessible form the host network by default.
Containers are procted by your host's firewall system.

Container wouldn't be very usefulif there were no way to get them through the network.

`-p=[]`, you can use to create a mapping between a port on the host's network stack and the new container's interface.

- docker run -p 80 ...
  Docker chooses a random port on the host machine and maps it to port 80 in the container, like 32768:80

- docker run -p 80:80
  Bind the port 80 in the host to port 80 in container

- docker run -it --rm -p 192.168.2.103::80 nginx
  Bind dynamic port on the interface with specified IP address, like 192.168.2.103:58684

- docker run -it --rm -p 192.168.2.103:8080::80 nginx
  Bind the container port to the specified port on the interface with the specified IP address.

# 5.7 Inter-container dependencies

Now that you've learned what kind of network containers you can build with Docker and how those containers interact with the network.

## 5.7.1 Intorducing links for local service discovery

When you create a new container, you can tell Docker to link it to any other container.
That target container must be running when the new container is created.

Containers hold their IP addresss only when they're running. If they're stopped, they lose that lease.

Adding a link on a new container does 3 things
1. Enviroment variables describing the target container's endpoint will be created.
2. The link alias will be added to the DNS override list of the new contaienr with the IP address of the target container.
3. If inter-container communication is disabled, Docker will add specific firewall reuls to allow communication between linked container.

The ports tha tare poend fo rcommunication are those that have been exposed by the taret container.
You need to provide `--expose` flag.

```sh
docker run --name importantData \
  --expose 3060 \
  -e MYSQL_ROOT_PASSWORD=my-secret-pw \
  -d mysql

docker run -d --name importWebapp \
  --link importantData:db \
  mysql \
  mysql -h db -P 3306 -u root -pmy-secret-pw -e "SHOW DATABASES;"

```

## 5.7.2 Link aliases

Support multiple `--link`. So, if three containers named a, b, c exist I could run the following:

```sh
docker run --link a:alias-a --link b:alias-b --link c:alias-c ...
```

## 5.7.3 Environment modifications

Creating a link will add connection information to a new container.
This connection information is injected in the new container by adding enviroment variables and host name paping in the DNS override system.

```sh
docker run -d --name mydb \
  --expose 2222 --expose 3333 --expose 4444/udp \
  alpine nc -l 0.0.0.0:2222

docker run -it --rm \
  --link mydb:database \
  dockerinaction/ch5_ff env
```
