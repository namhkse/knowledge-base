# 2.7 Socket Programming: Creating Network Application

When these two programs are executed, a client and a server process are created, adn these processes
communicate with each other by reading from, and writing to, sockets.
When createing a network application, the developer's main taks is therefore to write the code for
both the client and server programs.

## 2.7.1 Socket Programming with UDP

We'll write a simple client-server programs that use UDP.

Each process is a house and process's socket is a door.
The transport layer is in the outside world.

The developer has control of the application-layer of the socket.

Before the sending process can push a package of data out the socket door, when using UDP,
it must first attach a **destination address** to the package.

The Internet will use the **desination address** to route the packet through the Intenet.

When the package arives at the receving socket, the receiving process retrives the package through the socket,
and inspcect the packet's content.

Destination address = IP + port number

The simple client-server application:
1. The client reads a line from the keyboard and sends the line to the server.
2. The server receives the line and converts it to uppercase.
3. The server sends the uppercase line to the client.
4. The client recevies the modified lien and displays the line on its screen.

## 2.7.2 Socket Programming with TCP

TCP is a connection-oriented protocol.
Before the client and server can start to send data to each other, they first need to handshake and 
establish a TCP connection.
With the TCP connection established, when one side wants to send the other side, it just drops the data
into the TCP connection via its socket.

This is different from UDP, for which the server must attach a destination address to the packet before
dropping it into the socket.

The interaction of client and server programs in TCP.
The client has a job of initiating contach with the server.

TCP connection with the server. The three-way handshake is in the transport layer, completely invisible to
the client and server programs.
