# Chapter 2. Event-Driven Microservice Fundamentals

An event-driven microservice is a small application build to fulfill a specific bounded context.

Consumer microservices consume and process events from one or more input event streams

Producer microservices produce events to event streams for other services to consume.

It is common for an event-driven microservice to be a consumer and a producer.

These services may be stateless or stateful.

Event streams are served by an event broker. 

## Building Topologies

Topology, this term is often used to mean the processing logic of an individual microservice.   

It may also be used to refer to the graph-like relationship between individual microservices, event streams,
and request-response APIs.

### Microservice Topology

The microservice topology ingests event from event stream A and save them into a data store.
Meanwhile, event stream B is ingested, and certain events are filtered out, transformed, and
then joined against the stored state.

```
                    Microservice topology
Event Stream A ------------------------------[Data store] 
                                                   ↓ 
Event Stream B ----> Filter ----> Transform ----> Join ----> Output stream
```

The results are output to a new event stream.

### Business Topology

A business topology is the set of microservices, event streams, and APIs that fulfill complex
business functions.

> TIP
> A microservice topology deteails the inner workings of a single microservice. 
> A business topology on the other hand, details the relationships between services.

Microservice 1 consumes and transforms data from event stream A and produces the result
to event stream B.

Microservice 2 acts as a consumer adn provides a REST API in which data can be accessed
synchronously.

Microseervice 3 performs its own transformations according to its bounded context and outputs to event stream C.

## The Contents of an Event

An event can be anything that has happened within the scope of the business communication structure.

An event is a recording of what happened.

The Structure of an Event

Events are represented usign a key/value format.
The value stores the complete details of the event, while the key is used for identification
purposes, routing and aggregation operations on events with the same key.

There are 3 main events types:
- Unkeyed Event
- Entity Event: describe the properties and state of a entity.
- Keyed Event: contains a key but does not represent an entity.

## Materializing State from Entity Events

You can materialize a stateful table by applying entity events, in order, from an entity event stream.
Each entity event is upserted into the key/value table.

You can convert a table into a stream of event duality and it is fundamental to the creation of state in event-driven
microservice.

Compaction is performed by the event borker to reduce the size of its internla logs by retaining only the most recent event for a given key.

## Event Data Definitions and Schemas

Event data serves data storage and communication mechanism between service.

The producers and consumers of event shave a common understanding of the meaning of the data.

## Microservice Single Writer Principle

Each event stream has one and only one producing microservice.

## Powering Microservices with the Event Broker

The heart of every production is the event broker.

This is a system that receives events, stores them in a queue or partitioned event 
stream, and provides them for consumption by other processes.
