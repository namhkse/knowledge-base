# The Orchestration Pattern

A central microservice, the orchestrator, issues commands to and awaits response from subordinate
worker microservices.

The orchestrator microservice contains the entire workflow logic for a given business process
and sends spedific events to worker microservices to tell them waht to do.

> TIP:
> The orchestrator contains workflow logic. It should not contain business logic.

The orchestrator update its internal state based on te results returned from the worker microservice.

# Distributed Transaction

A distributed transaction is a transaction that spans two or more microservices. Each microservice
is responsible for processing its portion of the transaction.

Both fulfilment and reversal logic must reside within the same microservice.

## Choreographed Transactions: The Saga Pattern

Each service need to be able to roll back changes in teh event of a failure.

Good when:
- Simple distributed transactions.
- Strong workflow requirements, unlikely to change over time.
