# 3.2 Difficulities with element height

Normal document flow is design to work with a constrained widht and an unlimited height.

## Controlling overflow behavior

You explicitly set an element's height, you run the risk of its contents overflowing the container.

You can contorl the extract behavior of the overflowing content with the `overflow` property.

## Applying alternatives to percentage-based heights

Specifying height using a percentage is problematic.

The height of a container is typically determined by the height of its children.

One reason people try to use percentage-based heights is to make a container fill the screen. 

A better approach is to use the `vh` units.

Trick: use negative margin values to set column heights.

### CSS table layouts

You make teh container a `display: table`
and each column a `display: table-cell`.

### Flexbox

Accomplishing a two-column layout with equal-height columns can also be done with a flexbox.

By default, using a flexblox produces elements of equal height.
You won't have to worry about negative margins.

> Warning: Never explicitly set the height of an element unless you have no other choice.

## Using min-height and max-height

Two properties that can be helpful are min-height and max-height.

# 3.3 Negative margins

Unlike padding and border width, you can assign a negative value to margins.
The exact behavior depends on which side of the element you apply it to.

**Negative left and top margins**
If applied to the left or top, the negative margin moves the element leftward or upward

**Negative right and bottom margins**
If apllied to the right or bototm, the negative margin pulls the succeeding element(s) leftward or upward.

When a block element doesn't have a specified width, it naturally fills the width of its container.
A negative right margin, can change this, as long as no width is specified, it pulls the edge of the element to the right,
bringing it outside the container

Be sure not to use negative margin valeus too frequenlty.

# 3.4 Collapsed margins

When top/bottom margins are adjoining, they overlap.
They are combining to form a single margin. This is referred to as *collapsing*.

## Collapsing between text

By defalt, the `p` has a 1 em top margin and a 1 em bottom margin.

When you stack 2 paragraphs, one after the other, their margins dont' add upp to a gap of 2 em.
Instead they collapse, overlappign to produce one 1 em fo space between the two paragraphs.

## 3.4.2 Collapsing multiple margins

Elements don't have to be adjeacent siblings for their margins to collapse.

In short, any adjacent top and bottom margins will collapse together.

> NOTE: Margin collapsing only occurs with top and bottom margins.
> Left and right margins don't collapse.

## 3.4.3 Collapsing outside a container

An element's margin collapsing outside its container.

> Fixing trick: The margins of flexbox items don't collapse. So we set contaier's `display` to the `flex` value.

Here are ways to prevent margins from collapsing:
- MEDIUM - Add paddings.
- GOOD - Use `overflow: auto`.
- BAD - Set the container to the float, or inline-block, the margin will be in the container.
- GOOD - Set the contaier to the flex layout.
- VERY BAD - Using table-cell, this is complex.
